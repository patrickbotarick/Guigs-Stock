GUIG'S STOCK 1.2 — GUIA DE USO E INSTALAÇÃO
===========================================

VISÃO GERAL
-----------
O Guig's Stock é o sistema de controle de bebidas da Pizzaria Guig's.

A versão 1.2 utiliza Supabase para autenticação, sincronização entre usuários e armazenamento em nuvem.

Principais recursos:
- Cadastro e edição de produtos
- Recebimento de estoque
- Controle por lotes e validade
- Transferência entre estoque e geladeira
- Registro de vendas
- Registro de perdas
- Ajuste de inventário
- Histórico de movimentações
- Controle de permissões por usuário
- Sincronização entre computadores/sessões
- Proteção contra saldo negativo
- Proteção contra operações concorrentes


REQUISITOS
----------
- Windows 10 ou 11
- Google Chrome ou Microsoft Edge
- Conexão com a internet
- Conta cadastrada no Supabase
- Arquivo config.js configurado localmente


ESTRUTURA DE USUÁRIOS
---------------------

OWNER / PROPRIETÁRIO
Pode:
- cadastrar produtos
- editar produtos
- ativar/inativar produtos
- receber estoque
- transferir estoque ↔ geladeira
- registrar vendas
- registrar perdas
- ajustar inventário
- consultar histórico

ATTENDANT / ATENDENTE
Pode:
- receber estoque
- transferir estoque ↔ geladeira
- registrar vendas
- registrar perdas
- consultar histórico

Não pode:
- cadastrar produtos
- editar produtos
- ajustar inventário


CONFIGURAÇÃO INICIAL
--------------------

1. Clone ou copie a pasta do Guig's Stock para o computador.

2. Na pasta do projeto, copie:

config.example.js

e crie:

config.js

3. Preencha apenas:

- URL do projeto Supabase
- Publishable Key

IMPORTANTE:
Nunca coloque no config.js:
- service_role
- secret key
- qualquer chave administrativa do Supabase

O config.js não deve ser enviado ao GitHub.


COMO INICIAR
------------

Forma recomendada:

1. Abra a pasta do Guig's Stock.
2. Execute:

Abrir Guigs Stock.bat

O sistema deve iniciar o servidor local e abrir o navegador.

A porta utilizada normalmente é:

8082

Caso o iniciador padrão não funcione, também existem arquivos PowerShell de inicialização.


LOGIN
-----

Ao abrir o sistema, faça login com um usuário previamente cadastrado no Supabase.

O usuário também precisa estar vinculado à Pizzaria Guig's na tabela de memberships.

Se o usuário estiver autenticado mas sem vínculo ativo, o acesso ao estoque será bloqueado.


CADASTRO DE PRODUTOS
--------------------

Disponível apenas para OWNER.

No painel:

Novo produto

Informe:
- nome
- categoria
- estoque mínimo total
- estoque alvo total
- mínimo da geladeira
- alvo da geladeira

Produtos com o mesmo nome não podem ser duplicados.


EDIÇÃO DE PRODUTOS
------------------

Disponível apenas para OWNER.

É possível alterar:
- nome
- categoria
- mínimos
- metas
- situação do produto

Produtos podem ser marcados como:

Ativo
Inativo

Produtos inativos continuam no histórico e mantêm seus saldos, mas não aparecem para novos recebimentos.


RECEBIMENTO DE ESTOQUE
----------------------

Abra:

Receber estoque

Informe:
- produto
- código do lote
- validade
- quantidade
- observação opcional

Todo recebimento entra inicialmente no:

ESTOQUE

Não é permitido cadastrar lote já vencido.


TRANSFERÊNCIA
-------------

Abra:

Movimentar

Escolha:
- lote
- direção
- quantidade

Direções disponíveis:

Estoque → Geladeira
Geladeira → Estoque

O sistema verifica o saldo real no banco antes de concluir a operação.

Não é permitido criar saldo negativo.


VENDA
-----

Abra:

Venda

A venda sempre retira unidades da:

GELADEIRA

Lotes vencidos não podem ser vendidos.

O sistema bloqueia vendas acima do saldo disponível.


PERDA
-----

Abra:

Registrar perda

Informe:
- lote
- local
- quantidade
- motivo

A perda pode acontecer tanto no estoque quanto na geladeira.


AJUSTE DE INVENTÁRIO
--------------------

Disponível apenas para OWNER.

Use quando a contagem física for diferente do valor mostrado no sistema.

Exemplo:

Sistema:
15 unidades

Contagem física:
13 unidades

Ao informar 13, o sistema cria automaticamente:

Ajuste -2

Se o valor informado for igual ao saldo atual, nenhuma movimentação é criada.


HISTÓRICO
---------

Todas as operações ficam registradas na nuvem.

Tipos de movimentação:
- receipt
- transfer
- return
- sale
- loss
- adjust

Transferências geram duas linhas:
- saída da origem
- entrada no destino

As duas linhas compartilham o mesmo identificador de evento.


SINCRONIZAÇÃO ENTRE USUÁRIOS
----------------------------

Todos os usuários conectados à mesma pizzaria consultam o mesmo banco de dados.

Se um usuário fizer uma operação, outro usuário poderá visualizar a alteração ao atualizar o painel.

Antes de abrir operações importantes, o sistema também atualiza os dados para reduzir o risco de trabalhar com saldo antigo.


CONCORRÊNCIA
------------

O banco protege as movimentações contra operações simultâneas.

Exemplo:

Saldo disponível:
2 unidades

Usuário A tenta retirar:
2 unidades

Usuário B também tenta retirar:
2 unidades

Se o usuário A concluir primeiro, a operação do usuário B será bloqueada.

Isso impede saldo negativo mesmo que as duas interfaces mostrem dados antigos.


SEGURANÇA
---------

A segurança principal fica no Supabase.

O navegador não possui permissão direta para inserir, atualizar ou excluir registros das tabelas principais.

As operações de escrita utilizam funções RPC controladas pelo banco.

As permissões também são verificadas no banco:

OWNER:
acesso administrativo

ATTENDANT:
operações de estoque limitadas

Esconder um botão na interface não é considerado a proteção principal.

Mesmo uma chamada manual indevida deve ser rejeitada pelo banco.


BACKUP
------

Os dados operacionais da versão 1.2 ficam no Supabase.

O GitHub contém o código do sistema, não o banco de estoque.

Recomenda-se manter:
- repositório GitHub atualizado
- migrations SQL versionadas
- acesso administrativo ao projeto Supabase protegido
